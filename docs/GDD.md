## 二、核心设计

### 2.1 核心循环

> 完整循环：**摸黑探路 → 找到火柴/道具 → 避开敌人 → 记住房间与藏匿点 → 找齐三块碎片 → 从大门逃出去 → 重开一局**
>
> 玩家每 **10~30 秒**重复的一件事：**推开一扇门，在几乎全黑的房间里摸索，赌自己摸到的是碎片还是幽灵。**
>
> 节奏由两件事咬合：**视野极小**（只知道身边一圈）+ **火柴有限**（点燃才看得清整间房，但火光也让你更容易撞上敌人）。
> 紧张感不靠 jump scare、不靠追兵，靠的是**信息不足**：先怀疑房间，再怀疑自己的记忆，最后怀疑游戏本身。

### 2.2 核心机制 / 创新点

> 创新点**最多 1 个**，且必须是可砍的：

1. **（主项）视线与火柴的取舍** —— 火柴是"看清"也是"暴露"，玩家每次点燃都在做一次小赌博。这是原作已有的机制，**我们的活是把它的反馈做得更利落**（点燃/熄灭的瞬间、音效、敌人被吸引的判定）。
2. **（可砍加分项）打破第四面墙的轻量层** —— 只在画面与文本层面做暗示：找到的碎片是假的、屏幕上冒出不属于这个游戏的提示、幽灵在最后一刻把碎片换掉。理由：Discord 主题投票里 Horror 与 4th wall break 曾并列第一，**这一层同时兼容两种主题**，且不需要新系统。**工时不够就整条砍掉**（标记为"下一里程碑"，不排期）。

> ❌ 明确不做为"创新点"的方向：任何需要新系统的东西（随机地图生成、存档、多人、物理）。

### 2.3 操作与手感

> 目标平台网页优先 → **方向键 / WASD 移动 + 一个动作键（点燃火柴 / 拾取）**，不做鼠标瞄准、不做触屏。
> 手感要点：网格对齐的移动（不滑）、转身与开门要有可感知的停顿、受击反馈要短促而不是长动画。

**显示缩放方案（网格已定为 192×160，这里只决定"怎么放大到屏幕"）**

- 网格定为 **192×160** 后，**不再存在 Atari 原机那套 1.6:1 非方形像素**的问题 —— 直接按方形像素整数倍放大即可。
- 推荐：窗口 **768×640**（4×）或 **960×800**（5×），`Stretch Mode = viewport`、`Aspect = keep`、`Scale Mode = integer`。像素锐利、比例不失真、itch 嵌入也放得下。
- 备选：若想让画面显得更"宽银幕"，可把窗口设成 4:3（如 1024×768）并配 `Aspect = expand` —— 但这会**改变像素形状**，与"192×160 网格"的既定规格冲突，除非两人都同意。
- ⚠️ 前提是**不要在窗口比例上追求 4:3**：一旦追求 4:3，192×160 的内容就会被拉伸变形（192/160 = 1.2，而 4:3 = 1.333）。

**音频方向（Ray）**

- TIA 风格：2 声道、方波为主 + 噪声，短促、颗粒感强。
- 提交前转 `ogg`，避免 wav 撑大仓库。

**A. 要复刻的核心机制（✅ 2026-09-30 定案 —— 只做机制，资产全部自研）**

1. **主角与视野** —— 主角就是"一双眼睛"；房间里几乎全黑，只有自己周围一小圈可见。
2. **光源** —— 火柴：点燃可短暂照亮整间房，数量有限，屋里能捡到。
3. **目标物** —— 魔法瓮的三块碎片，散落在宅邸的藏匿点里。
4. **出口** —— 找齐碎片后必须**从大门走出去**才算赢（不是"拿到即通关"）。
5. **敌人** —— 蝙蝠 / 蜘蛛 / 幽灵，行为各不相同（默认设想：蝙蝠乱飞、蜘蛛守房间、幽灵巡楼）。
6. **空间** —— 多层宅邸，房间按网格排布；走出房间边缘会从对侧穿回（环绕）。
7. **判定** —— 碰到敌人扣命并被送回入口。

**D2. 命名规范**
