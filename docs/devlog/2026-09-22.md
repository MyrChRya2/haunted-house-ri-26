## 决策与理由

- **单独复制一个 PM Agent，而不是复用长期项目的「项目管理」** → 两个项目必须隔离，且 Jam 结束后要把经验反哺回原 Agent，复制体是干净的试验田。
- **飞书 Agent 的 cwd 钉到本工作区，而不是默认的 `~/.dsh-feishu`** → team-comms 按 cwd 分队：只有钉到本工作区，飞书里的 Agent 才和本项目的角色同队，文档也才落在这里。与长期项目 cwd 不同，因此天然隔离。
- **保留 team-comms 接口而不是卸载** → 用户明确要求"保留团队接口以便未来拉人组队"；先登记角色，等加人时直接可用。
- **不装 `dsh-plugin-subagent-director`** → 它会引入第三套 preset→角色映射，与 team-comms 的角色表打架。
- **不改 `project-management` skill 本身** → 它是全局的，改动会波及长期项目；Jam 的多人协作约定写在 `PROJECT_INDEX.md` 第五节，由 skill 读取。
- **不采用启动路径文档第 5 节的 `subagent`/`workflow` 作为编排核心** → team-comms 的常驻角色+直投+决策队列更强（有跨会话记忆、落盘、离线补收）；`subagent` 仅在单次并行任务时作补充。

## 踩坑 / 问题

- **`dsh plugin add github:...` 失败**：本机 git 配了 `socks5://127.0.0.1:7890` 代理但代理没开，`git ls-remote` 连不上 GitHub（而 PowerShell 直连正常）。
  → 改用官方 Release 的 tgz 安装（README 推荐的备选路径），并把 tgz 存到 `~/.dsh/plugins/artifacts/` 以免被临时目录清理。
- **`ERR_PNPM_IGNORED_BUILDS`（protobufjs）**：pnpm 拦下 postinstall，按 README 提示把 profile `pnpm-workspace.yaml` 里的占位行 `protobufjs: null` 改成 `true` 后重跑即可。其 postinstall 只打印版本提示。
- **飞书插件配置是"整体替换"不是"深合并"**：`cordis.patch.yml` 里的非 insert 补丁项会**整个替换**目标行的 `config`（`applyEntryPatches` 里是 `target[key] = value`），所以必须把该行需要的每个键都列全，否则会被清空。
