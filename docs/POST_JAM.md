## 二、复盘会议程（建议 60~90 分钟，Ray + Illya）

> 建议按顺序聊，前三条是"事实对齐"，后四条是"经验沉淀"。**每条都写：结论 + 下一步谁做**。

1. **时间盒**：为什么会连续 4 天（10-01~10-04）零提交，而 M1/M2 的目标日期当时没有任何人核对？下次用什么机制兜住（例会？ROADMAP 日期告警？Agent 开场强制核对？）
2. **范围取舍**：计划从"三层楼 + 3 碎片 + 3 敌人"砍到"1 房间 + 1 怪"，最终却交了 **10 间房 + 3 怪 + 13 段音效 + 10 关容器**。是砍错了，还是"砍"只是纸面动作？范围到底怎么定才有效？
3. **交付链路**：首次试传拖到截止前 30 小时 → 最后 24 小时里 `index.html` 入口、重导出、**漏点 Submit** 全挤在一起。下次的"链路验收"放在哪个时间点、由谁负责？
4. **协作接口**："接口先行"真的起作用了吗 —— 方法名对不上导致扣血静默失效、素材来源无审计（B2）、动了对方独占的 `project.godot`。哪些约定该保留、哪些形同虚设？
5. **版权与合规**：B2 差点成版权事故、字体许可最后靠读 `.ttf` 的 `name` 表才确认。下次"素材来源台账"从第几天开始建？
6. **AI 边界**：这次全程由 Agent 做项目管理/Git/台账/导出。哪些让 AI 做是对的？哪些该人做？AI 用在哪一步能省最多时间？
7. **文档与台账的性价比**：`docs/`（GDD/ROADMAP/devlog/飞书镜像/记忆库）哪些真正被用到，哪些只是负担？下个项目保留哪几样？
8. **最终结论**：这次最大的教训一条、最值得保留的做法一条、下次要改的三件事（各带归属）。

## 四、这次已经沉淀成规则的教训（不必再讨论，直接用）

1. **有硬截止的项目，时间是第一个要看的东西** —— 开场与每次汇报都先算"距截止还有几小时"，并重写 ROADMAP 里过期的"剩余小时"。
2. **"上传成功 / 页面公开" ≠ "已提交"** —— 交付完成标准写成"在收件方名单里能看到"，验证从收件方视角做。
3. **交付链路的首次验证必须提前用占位包跑通** —— 别把"能不能交上去"留到最后一天。
4. **别人说"已经清掉了"时，去验引用** —— 逐项 `git grep` 归零 + 查悬空 `.import` + 查入口配置。
5. **改名 / 移动要连带处理 `.import` 与引用**；`git diff` 里的 `R`（改名）条目要核对两端路径。
6. **AI 边界**：Agent 做项目管理、台账、Git、工程配置与构建，不写游戏代码、不生成素材、不代建场景；"能不能玩"必须由人在真机验。
